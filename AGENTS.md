# Agent start here: research, video, and website work

This public repository is the durable instruction hub for the Paper Channel. Read this file before any research selection, script, video, thumbnail, catalog, or code change. Then read:

1. [Research and video checklist](tools/papers/PRODUCTION.md).
2. [Approved visual contract and concrete examples](tools/papers/THUMBNAILS.md). Actually inspect the referenced image assets, not just this prose.
3. [Catalog and publication workflow](tools/papers/README.md), including required metadata and exact commands.
4. [Resumable publication queue](tools/papers/QUEUE.md). Reconcile unfinished episodes before starting another batch; keep its state private.

## Non-negotiable continuity

Use the existing charcoal/cream/teal editorial design, Playfair Display titles and JetBrains Mono labels. Follow `editorial-frame-v1` across production dates. The approved existing `spectral-eeg.jpg` frame is the principal reference; `timecap.jpg` and `latent-editorial.jpg` show compatible variations. Preserve shared card layout, full scientific titles, accessibility, and responsive behavior. Do not replace the site design or use arbitrary raw figure crops as cards. Change the central scientific content, not the visual system.

## Research and video

For future nine-paper batches: **2 own-research/memory papers, 2–3 health/medical-AI papers, and 4–5 free-choice papers** selected for verified attention, influence, or novel reusable techniques worth learning. Do not reinterpret already-produced batches. Keep evidence quality above quotas; disclose a verified shortfall rather than padding.

Verify primary full text, methods/results and metadata; deduplicate by paper ID/DOI/version against the canonical archive and prior catalog. Separate author claims, independent verification, speculation and clinical readiness. Write the evidence-checked script before storyboard, synthesize the approved Pocket TTS Anna voice, measure each section, and time visuals/subtitles to that actual audio. Explain actors, inputs, targets and changed parameters before jargon. Use original technical figures when permitted and readable; label adaptations and preserve source credits.

Each paper gets a separate horizontal 16:9 explainer, at most five minutes of explanation; official demos are additional and separately timed. Never silently switch voice. Verify full decode, audio presence/playback, timing/subtitles, scientific fidelity, and actual phone/desktop figure legibility. Generated-speech transcription/listening-versus-script checks are intentionally not required; do not install a speech checker or claim that check was performed.

## Coding and publication

Inspect repository status and current remote first. Preserve unrelated edits and stable file identities; coordinate one writer. Edit catalog sources/templates, then regenerate, not generated HTML by hand. Run the build/unit/public-boundary checks and responsive browser tests documented below. Tests do not replace real public video playback and visual QA.

For the authorized daily workflow, publish each finished, QA-passed episode as soon as it is ready; do not wait for the whole batch. First verify its specific video and transcript are publicly accessible, then update the catalog, deploy using the existing workflow, and verify the exact live version, links, playback and layout. Do not mark inaccessible or incomplete episodes ready. General edits still require appropriate publication authority. Never start Codex or Work sessions for this workflow unless the user explicitly changes that restriction.

## Privacy and permissions

The repository and its history are public even for files excluded from Pages. Never commit private research notes, account or Library IDs, credentials, source PDFs, production packages, intermediate audio, sensitive screenshots or access troubleshooting. Keep deeper companion/research and generation materials in the authorized private archive; clean presentation folders contain latest videos, plain-text transcripts and paper links only. Specific finished-media publication authority does not authorize whole-folder sharing, spending, new credentials or permission bypasses. Report precise blockers and never claim an unverified change occurred.
