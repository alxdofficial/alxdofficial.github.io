Continual Learning Exam: Benchmarking Long-Horizon RSI and Experiential Learning in LLM Agents

Linked professional assignments expose long-horizon agent weaknesses.

THE TAKEAWAY

Use matched memory-reset and equal-budget controls.

KEEP IN MIND

Fixed parameters and an extra feedback attempt do not establish recursive self-improvement.

1. Problem

Does an agent learn from doing work, or merely solve a fresh task each time? Continual Learning Exam is a benchmark designed to expose that distinction. It contains one hundred twenty professional tasks, each with five connected levels. Passing one assignment unlocks the next; later work can require earlier files, procedures or preferences. The original task-design panel shows this ladder. The benchmark evaluates a complete language-model agent, including its persistent memory and tools, rather than treating the language model alone as the system that learns.

2. Why it matters

A successful first answer says little about whether an agent can retain lessons and use them later. Here, software maintenance, analysis and other professional assignments evolve within a shared context. Fifty-plus experts created six hundred levels across twelve occupational domains, with real input files and human-written grading criteria. The intended application is evaluating long-horizon professional assistants. These are simulated workflows with stateful mock applications, not evidence that the agents are ready to perform the corresponding real occupations without supervision.

3. Prior approaches and learning loop

The paper distinguishes learning inside fixed model weights from changing an agent’s external working state. In the reported experiments, the model parameters stay frozen. The agent reads task inputs, chooses tool calls, receives observations and may retain experience in its harness: the surrounding software that manages context, memory and skills. Later decisions can use that retained state. This is not evidence of weight-level continual training. The title also mentions recursive self-improvement, meaning improving the process that learns; the benchmark’s scores alone do not demonstrate that stronger claim.

4. Evaluation mechanism

Each task uses persistent application records across its five levels, but a new task starts with fresh task files and application databases. Harness memory persists across the fixed task order. A separate evaluation agent checks submitted artifacts against hidden, human-authored binary checklist items. Every item must pass. Trial one permits one submission without diagnostic feedback. Trial two permits a failed submission to receive category-level feedback and then one revision. Unreached levels count as failures, so early mistakes block later credit. The comparison changes both feedback and the opportunity to submit again.

5. Results

Across seventeen model-and-harness configurations, the authors report a median improvement of 5.33 percentage points with feedback and revision. The strongest tested configuration, Claude Code with Opus five, clears 47.67 percent of all six hundred levels in trial two, but completes all five levels in only twenty-eight of one hundred twenty tasks. Its reported run uses 520.62 million actor tokens and 58.90 active hours. These are author-reported benchmark results, not an independently verified universal ranking. The original charts also show that benefits vary by configuration and one system declines.

6. Relevance and caveats

For continual-memory research, the useful next experiment is a matched comparison that resets memory before each task while holding models, budgets and feedback fixed. The paper explicitly identifies this missing control. Grader agreement with human labels is reported as 96.86 percent per checklist item, which does not eliminate whole-task grading error. Public materials include a smaller CLE Lite release; the complete rubric packages require access approval. The reusable idea is to measure retained experience through linked assignments, while reporting full-ladder completion, resource costs and memory-reset controls alongside aggregate scores.
