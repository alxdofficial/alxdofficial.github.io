HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents

A fixed coding model uses calibrated cameras, geometric measurements and a repair agent to develop robot tools. Frozen tools reach 39.7% success under RoboDojo's aggregation, while fine contact and paused-simulation latency remain substantial limitations.

Original paper: Figure 3 / optimizer agent · Gao et al., HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents, arXiv:2610.23479v1 (2026). THE TAKEAWAY

Persistent software repairs can improve simulated manipulation without changing model weights.

KEEP IN MIND

The leaderboard comparison uses different evaluation samples; development includes inherited tools and human assistance, and the full harness is not released.

READ / COMPLETE NARRATION

The transcript.

1 / Actors and persistent updates Give a robot a coding agent, three cameras, and a small command interface. When an attempt fails, let another copy of the agent repair the code that caused the failure. Freeze those repairs, and test them on new scenes. That is the experiment in HexaShell, a robotics preprint from Hongcheng Gao and colleagues.

The important detail is where learning happens. The language model's weights stay fixed. What changes is a library of small programs for measuring objects and executing motions. One agent acts. Another reads its logs, diagnoses a failure, edits a tool and runs checks. The repaired tool survives into the next episode.

2 / Pixels to metric motion The harness translates commands into robot motion. It does not supply a task strategy. The agent sees a head camera, two wrist cameras, camera calibration and the robot's own state. It cannot look up the simulator's hidden object positions.

So how does it turn a pixel into a grasp? A calibrated pixel defines a ray through space. If the target lies on a measured plane, intersect that ray with the plane. If two cameras see the same point, triangulate their rays. When the head view is insufficient, move a wrist camera and measure again. Those viewing motions count against the robot's action budget.

3 / One concrete repair This sounds classical because the geometry is classical. The contribution is getting an agent to build, debug and reuse it. In one example, a xylophone tool mislocated a held mallet by about twenty-three millimeters. The repair matched a second view and triangulated its center. On the next attempt, the error was 2.7 millimeters and the task succeeded.

4 / Results and sample mismatch Now the results. Across forty-two simulated RoboDojo tasks, the frozen tools achieve 39.7 percent success using the leaderboard's aggregation formula. The paper compares that with 32.3 percent for the strongest learned-policy entry in its October fourteenth snapshot. That competitor, VPP2, learns a visual planner and an action model from manipulation data.

But these are different evaluation samples. HexaShell tests ten new layouts on one seed per task; leaderboard entries use fifty episodes on each of three seeds. The agent also receives task recipes and tool notes. So this is an encouraging reported comparison, with clear limits on the ranking claim.

5 / Controlled evidence and failures The cleaner ablation is the geometry choice. On the same development layouts, triangulation scores 38.3 percent versus 29.6 percent for a monocular depth network. It uniquely solves fifty-seven layouts and loses twenty-three. Extra views help, even though moving the cameras consumes steps.

The failures are revealing. Pushing reaches 92.5 percent, while tight insertion reaches only 8.3 percent. Nineteen task variants never succeed. Better scene measurement does not automatically produce the continuous corrections needed when a part contacts a tight opening.

6 / Costs and useful scope There is a substantial time bill. A typical test episode takes about twelve minutes of wall time for twenty-six seconds of simulated robot motion. The simulator pauses while the model thinks. Development requires hundreds of repair rounds, and some tools descend from earlier depth-based and human-assisted work. The public release includes the tools but omits the full harness.

The demonstrated application is therefore simulated robot-tool development. Real-time physical deployment remains untested. What makes this paper worth watching is the inspectable learning loop: failures become concrete software fixes, and the evaluation shows both where those fixes help and where contact control still defeats them.
