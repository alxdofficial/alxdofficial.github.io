1. 1 / Problem
An agent solving different kinds of tasks should not learn from every earlier interaction in the same way. A past database query may be useful as an example; a stream of noisy measurements needs an estimate, not pages of conversation. Routed Continual Learning asks two coupled questions: which experiences should share memory, and what form should that memory take? This is adaptation of external state, not continual fine-tuning of language-model weights.

2. 2 / Why difficult
One global conversation history retains details but spends tokens on irrelevant experience. One compressed summary saves space but can discard information needed later. Splitting memory too aggressively prevents transfer; combining unrelated cases creates interference. The paper studies a stream where task labels are hidden, although the visible prompts, tool interfaces, and response formats can still reveal substantial task structure.

3. 3 / Applications and prior approaches
The evaluation interleaves 301 problems from Continual Learning Bench, a benchmark of six stateful agent tasks, with 97 banking-service conversations from tau-three Bench. Five matched runs preserve ordering within each task. Comparisons progressively add memory: no shared history, one global history, several routed histories, and routing across different memory mechanisms. Each condition uses the same actor, task interfaces, and budgets. These are controlled benchmark comparisons, not a verified ranking of all current memory systems.

4. 4 / Method
Before an agent starts, a prompted language model reads its current request, descriptions of available memory mechanisms, and brief cluster summaries. It either reuses a cluster or creates one; that choice stays fixed for the run. The router is not trained and cannot read the clusters’ raw histories. The selected memory returns advice that is inserted beside the unchanged task prompt. After execution, only that cluster receives the visible trajectory. Language-model parameters remain unchanged. The fixed library includes complete histories, reusable reasoning lessons, and three statistical memories for scalar outcomes, event-probability curves, and noisy persistent entities. For numerical memories, a configuration layer maps visible fields into a restricted schema, checks extracted evidence, and fits or updates statistical state. It does not generate new memory algorithms or submit answers. Hidden evaluation rewards never enter this process.

5. 5 / Results
The main score averages seven tasks equally. For six tasks, zero denotes an external stateless reference and one the task maximum; banking uses its native reward. With GPT-five-point-six Sol, mean normalized reward rises from 0.168 for global history to 0.387 for routed histories and 0.464 for full routing. Estimated cost per 398-problem run falls from 456 dollars to 170 dollars to 126 dollars. These are author estimates including every model call and caching, not current price quotes. Across four models, full routing saves 65 to 72 percent against global history. But its gain beyond routed histories is only 0.002 for Gemini, and it costs five percent more than routed histories for Opus four-point-seven.

6. 6 / Relevance and caveats
The reusable idea is to select a memory representation together with its sharing boundary, rather than searching one universal store. The memory library was developed on this benchmark before being frozen. Evaluation is sequential, uses one model for every role in a run, and does not test simultaneous updates or cross-model sharing. Five rollouts and uneven task-level wins limit generalization. For persistent agents, treat this as a promising routing design with measured tradeoffs, not proof of unrestricted lifelong learning.
